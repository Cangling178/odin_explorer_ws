# 实车接入、联调与标定

[English](09_bringup.md) | 简体中文

截至 2026-09-21 仓库核对，仿真循迹可运行；上位机硬件适配、F4 通信、真实轮式里程计和比赛启动仍未完成。设备接入已有证据限于厂商驱动开发机构建及点云显示，见[厂商记录](../vendor_ws/README_cn.md)。

## 1. 核对硬件与规则

填写 [BOM](../hardware/bom.csv)、[机器人规格](../hardware/robot_spec.template.yaml)和[平台版本](../hardware/platform_lock.template.yaml)。机械资料已记录 MG513X GMR 500 线、1:28 参考电机；额定电压／电流、编码器计数含义、实际开发板、驱动器及通信仍待核实。“F4”不能确定引脚或工具链。

核对载板、内存、JetPack／系统、设备固件、USB 链路和供电接线。记录电池、稳压器、保险丝、停止回路、接地和线缆固定，按实物额定值检查；测量带载压降、温升和断连。按[需求](01_requirements_cn.md)确认赛道尺寸、方向、交叉点顺序、评分参考点与容差。

## 2. 轮速台架

车轮离地时核对方向、实测编码器计数、有界轮速指令与反馈。实现并验证 [F4 协议](../firmware/README_cn.md)：错误／过期／重复包、重连、复位、饱和与看门狗。拔通信或重启上位机应使电机停止，且需主动重新使能。分别记录实际停车延迟／距离与超时设置。

## 3. ODIN 图像与静止投影

加载已审阅的厂商版本，核对真实话题、类型、坐标、QoS 和采集时间。在实际安装与预期照明下采集直线、紧弯、交叉点，测量近远地面视野、黑线像素宽度、曝光及处理延迟。

仓库 2026-09-16 的厂商源码检查发现 `odin1/image`，未发现配套 CameraInfo 发布，接入时应按实际安装版本复查。当前 `line_perception` 要求图像与 CameraInfo 的时间戳及尺寸匹配、自定义 `fishpoly` 模型和采集时刻 TF。`racer_odin` 需提供对应标定并保留采集时间，区分原始与去畸变图像。[FishPoly 约定](../simulation/FISHPOLY_CAMERA_cn.md)不能直接替换为 OpenCV fisheye 系数。

实测 `base_link -> ODIN1`、安装高度／俯仰和地面平面。已有[设备标定](../hardware/mechanical/odin1/calib_device.yaml)不等于车体安装标定。移动前用已知地面点核对投影及自遮挡；视野不足时先改安装／标定，或评估规则允许的普通相机，仍不使用专用循迹模块。

## 4. 运动标定与简单循线

测量带载滚动周长和每轮一圈计数，明确正交倍频及减速比。通过前后直行拟合距离比例并保留残差，在实际地面低速转向／圆弧上估计有效轮距，再换速度验证。检查被动支撑重新对齐、打滑和左右不对称，不照搬仿真的 1.10 轮距修正。

核对 TF 发布归属与设备复位语义，实测采集到回调、指令到运动的延迟、时钟偏移及重启变化，保留原始时间与不确定度。从直线和大圆弧开始，独立测量偏差；先验证无效输入停车，再测试降级运行。

## 5. 实测路线与完整跑圈

测量赛板角点、内部参考点、有序中心线、线宽及不确定度；坐标相同的交叉点访问仍要区分。按完整车体轮廓和允许走廊验证紧弯，再运行正式路线。用标定后的俯视测量或其他独立参考评估误差；重复验证后再提速，保留失败。预测制动需要实测执行器响应。

每版标定保存在 `hardware/calibration/<revision>/`，记录设备 ID、日期、单位、原始数据／哈希、残差、条件和不确定度。车轮、载荷、支撑或相机配置变化后重新标定。该位置目前没有实测标定结果，获得测量后再创建。

## 故障定位

| 现象 | 优先检查 |
| --- | --- |
| 转向错误或 TF 漂移 | 编码器／IMU 符号、变换方向、竞争发布、厂商重定位 |
| 直线振荡 | 时间戳延迟、轮速响应、前视和曝光 |
| 交叉点错分支 | 有序进度关联与位姿校正 |
| 紧弯切线 | 转弯可行性、前视、速度和扫掠轮廓 |
| 带载传感器断连 | 压降、USB／线缆和温度 |
| 内部误差小但肉眼漂移 | 标定、参考系和独立测量 |

当前没有实车 `race.launch.py`，仿真启动文件不能当作硬件部署入口。剩余任务和验收关卡统一见[项目计划](planning/README_cn.md)。
