# 实车开发三人分工明细

[English](TEAM_ASSIGNMENTS.md) | 简体中文

更新日期：2026-09-21。人员姓名待分配，本文按岗位约定任务和交付边界，不表示相关实车功能已经完成。

## 目标与当前基础

近期共同目标：打通 Jetson、ODIN1 和 F4，完成可重复的实车低速直线、圆弧循迹，再推进正确整圈与性能优化。

当前已有 C++ 感知、单分支循迹、预录路线辅助整圈控制及仿真评测。0.05 m/s 整圈仿真已三次重复通过，0.10 m/s 仅单次通过；这些成绩不代表实车验收完成。F4 通信和真实底盘接入尚未实现，ODIN1 已有开发笔记本驱动构建与点云初检，Jetson 组合、真实图像投影和标定仍待验证。

第 4 人承担总负责、系统集成和独立验收。本文仅列其与前三人的交接责任，不展开其完整任务。

## 人员 1：F4 下位机、底盘驱动与 Jetson 通信

### 职责和代码范围

负责从 Jetson 轮速目标到真实车轮运动、再到轮反馈返回的完整链路，包括上位机硬件适配代码。

- 固件与通信协议：`firmware/`。
- Jetson 硬件适配：`src/odin_racer/racer_hardware/`。
- 硬件参数、接线和轮速标定记录：`hardware/`。

### 前置条件

确认具体 F4 板、电机、驱动器、编码器、减速比、供电、引脚和停止接线；与总负责人确定串口或 CAN 及上位机硬件接口。当前这些信息尚未完整确认。确认前可整理协议草案和模拟通信测试，但不能用猜测参数替代实测规格。

### 任务顺序

1. 整理硬件清单、接线图、编码器计数关系、轮子方向和物理单位。
2. 完成编码器采集、电机输出及左右轮速度闭环，记录阶跃响应、稳态误差和低速表现。
3. 与总负责人固化通信协议：版本、帧格式、字节序、单位、序列号、校验、使能、反馈、故障和重启语义。
4. 实现 Jetson 侧读写与 F4 侧解析；反馈累计轮位置或计数、轮速、设备采样时间及状态。
5. 实现明确使能、目标限幅、指令超时停车和异常恢复，防止旧数据包重新使能。
6. 配合总负责人接入差速控制器；实测轮径、轮距和轮速比例，完成直行、转向和停车验证。

### 交付接口与成果

| 项目 | 要求 |
| --- | --- |
| 接收目标 | 左右轮角速度，单位 rad/s，明确车轮顺序、方向和使能状态 |
| 输出反馈 | 轮位置 rad 或可换算的累计计数、轮速 rad/s、采样时间、故障与使能状态 |
| 运动学边界 | 按当前方案由上位机差速控制器将车体速度换算为轮速；F4 执行轮速闭环 |
| 交付文件 | 固件源码、可复现构建和刷写说明、版本化协议、Jetson 适配代码、接线和参数记录 |
| 测试依据 | 通信往返日志、轮速响应曲线、异常输入和断连停车记录 |

轮反馈传输由人员 1 负责；差速控制器配置、里程计输出和 `odom → base_link` 发布归属由总负责人集成确认。

### 验收标准

- 左右轮目标、方向、单位及反馈一致，速度闭环误差满足联调前约定的门限。
- 能完成低速直行、左右转向和停车，报告指令到反馈的延迟和实际反馈频率。
- 错误校验、截断帧、重复或乱序数据、超限目标、断连和设备重启均有测试结果。
- 上位机停止发送或通信中断时，下位机按约定超时停止；重连后不自行恢复运动。

## 人员 2：ODIN1 与 Jetson 接入、标定和数据采集

### 职责和代码范围

负责交付算法可以直接使用、时间和空间含义明确的传感器数据。

- 厂商驱动工作空间：`vendor_ws/`，保留独立版本记录。
- 自研适配层：`src/odin_racer/racer_odin/`。
- 传感器模型和安装外参：`src/odin_racer/racer_description/` 中的相关配置，与总负责人协调修改。
- 标定记录：`hardware/calibration/`；原始数据：`data/`。

### 前置条件

需要实际 ODIN1、Jetson 及载板信息、匹配的设备固件和驱动、可用 USB 链路及正确供电。移动数据采集依赖可控运动，但静态图像、标定核对和地面视野验证可先独立开展。

### 任务顺序

1. 记录 Jetson 系统、ROS、设备固件及厂商驱动版本，在目标平台构建并验证连接。
2. 核对真实图像、IMU、点云和位姿话题的类型、坐标系、时间戳、频率及 QoS；优先打通循迹必需的图像链路。
3. 核对原始图像与去畸变图像，使用与所选图像一致的设备相机模型及标定。
4. 在适配层提供匹配的 `CameraInfo`，保留图像采集时间；当前感知要求两者时间戳完全一致，且使用 FishPoly 模型。
5. 测量相机相对车体的安装外参和地面几何，与总负责人完成 TF 配置。
6. 采集直线、圆弧、紧弯和交叉点图像，覆盖预期照明，记录最近和最远可见地面范围。
7. 提供可回放数据包；移动试验与总负责人同步录制里程计、TF、指令及运行状态。
8. 验证持续运行、设备重连、驱动重启和带载时的数据稳定性。

### 交付接口与成果

| 项目 | 要求 |
| --- | --- |
| 图像 | `sensor_msgs/Image`，编码、分辨率、光学坐标系和采集时间明确 |
| 相机标定 | `sensor_msgs/CameraInfo`，模型与实际图像一致，与图像按当前接口精确配时 |
| 安装关系 | 版本化车体到相机外参和测量依据，由总负责人统一 TF 发布归属 |
| 其他数据 | 记录 IMU、点云和位姿的单位、参考系、时钟及复位行为，按实际需求接入 |
| 交付文件 | 驱动版本记录、适配节点与配置、启动说明、标定文件、数据包索引和验证报告 |

规划中的 `/sensors/odin/*` 名称不是厂商实际话题的保证；最终重映射由人员 2 与总负责人记录。数据和标定正确性由人员 2 负责，黑线提取和匹配算法由人员 3 负责。

### 验收标准

- Jetson 持续收到有效数据，报告频率、传输延迟、丢帧和资源占用。
- 图像、CameraInfo 和 TF 满足现有感知输入要求，明确地面投影误差。
- 实际安装下能观察所需前视区域的黑线；向人员 3 提供可复现的直线、弯道和交叉点样本。
- 数据过期、设备断连和重启可识别，不通过重新打当前时间戳掩盖旧数据。
- 数据包和配置可在约定环境回放，包含版本、场景及采集条件说明。

## 人员 3：感知、循迹算法与实车适配

### 职责和代码范围

负责将有效的传感器及运动状态输入转为路线跟踪指令，完成真实数据适配、低速闭环及后续精度和速度优化。

- 感知：`src/odin_racer/racer_perception/`。
- 跟踪控制：`src/odin_racer/racer_control/`，包括 `line_controller.cpp`、`lap_controller.cpp`。
- 路线组织：`src/odin_racer/racer_trajectory/`、`tracks/` 和 `tools/generate_competition_lap.py`。
- 算法回归和分析：相关 `tools/`、`tests/`；独立验收门限与总负责人共同确定。

### 前置条件与当前状态

| 阶段 | 前置条件 | 当前状态 |
| --- | --- | --- |
| 仿真开发 | 图像、标定、TF、轮式里程计、执行模型、路线和评测器 | 已具备，核心整圈算法已实现，可立即开展重复及扰动测试 |
| 真实图像离线验证 | 实拍数据、正确内参、安装外参和场景记录 | 尚未完成接入验收，由人员 2 提供；不必等待 F4 完成 |
| 移动数据回放 | 上述输入加采集时刻的同步 TF 和运动状态 | 由人员 1、2 与总负责人共同准备 |
| 实车直线和圆弧循迹 | 可用感知输入、可靠轮速执行和反馈、连续里程计、统一时序及停车机制 | 尚未打通完整实车链路 |
| 正确完整整圈 | 基础闭环、实测有序路线、正式起点方向和交叉点顺序、紧弯通行验证 | 尚未完整确认 |
| 实车性能优化 | 可重复的低速路线基线及独立误差测量 | 待上述阶段通过后开展 |

仿真功能已完成不等于实车算法验收完成。基本实车循迹由四人共同交付，人员 3 不单独承担硬件和系统链路的实现。

### 任务顺序

1. 熟悉并保留现有基线：单分支循线与整圈控制的适用场景不同，记录代码版本和配置。
2. 在硬件准备期间补充仿真重复、起点偏差、图像失效和里程计扰动测试，保留失败案例。
3. 与人员 2 约定数据采集要求，离线检查黑线识别、地面投影、置信度和视觉匹配结果。
4. 对真实数据调整算法及参数；区分标定问题、识别问题和匹配问题，记录原因。
5. 与总负责人联调实车低速直线和圆弧，验证误差、执行延迟以及图像和里程计失效停车。
6. 根据实测路线完成交叉点、紧弯、起终点和连续整圈验证；保留有序进度约束。
7. 先达到可重复的精度基线，再优化前视距离、曲率限速、提前制动和速度曲线；不以放宽门限换取提速结果。

### 交付接口与成果

| 项目 | 要求 |
| --- | --- |
| 输入 | 图像及匹配 CameraInfo、TF、连续里程计、有序参考路线和运行配置 |
| 感知内部接口 | 沿用 `racer_interfaces/LineObservation`；整圈控制还使用地面黑线掩膜 |
| 输出 | `geometry_msgs/TwistStamped` 自主驾驶目标，附状态和诊断依据 |
| 控制边界 | 人员 3 负责自主指令；总负责人负责模式选择和最终指令入口；人员 1 负责执行和底层超时停车 |
| 交付文件 | 算法代码、配置版本、路线来源、回放方法、回归报告和失败样本分析 |

### 验收标准

- 真实样本的黑线和投影结果可视化可检查，失败场景有明确记录。
- 简单实车路线可重复循迹，输入失效时停止且不会自动恢复运动。
- 完整路线按规定顺序通过交叉点和检查点，终点停车，避免跳分支或抄近路。
- 报告成功率、时间加权 RMS、最大误差、有效数据覆盖、圈时和全部失败；实际误差由总负责人组织独立测量，不能仅用控制器内部估计作为真值。
- 每次优化比较同等条件和固定门限下的结果；实车数值标准依照需求草案、实测能力和正式规则在试验前确定。

## 共同接口与交接安排

### 开始开发前共同确定

- 人员 1 与总负责人：通信方式、协议版本、轮子顺序和方向、目标与反馈频率、时钟、限幅、使能和超时。
- 人员 2、3 与总负责人：图像模型、话题、时间戳、QoS、安装外参和 TF 唯一发布者。
- 人员 3 与总负责人：里程计输入、自主指令出口、模式切换、故障恢复和路线配置格式。
- 全员：采集与回放流程、版本归档、试验门限及失败报告格式。待定参数明确标为待定，不当作已冻结接口。

### 分阶段交接

| 阶段 | 人员 1 | 人员 2 | 人员 3 | 交接给总负责人的成果 |
| --- | --- | --- | --- | --- |
| A 设备准备 | 电机台架、通信及轮反馈 | Jetson 驱动、真实图像、初步标定 | 仿真回归、数据采集要求 | 底盘和相机可分别启动测试 |
| B 简单闭环 | 驱动参数和运动误差标定 | 地面投影验证、同步采集 | 直线圆弧跟踪、失效停车 | 实车低速闭环及独立误差报告 |
| C 完整路线 | 排查执行误差和打滑 | 排查视野、时序及图像失效 | 紧弯、交叉点、有序整圈 | 完整路线结果及全部失败记录 |
| D 性能优化 | 验证更高目标下的执行能力 | 验证运动下图像质量和延迟 | 精度、前视和速度曲线优化 | 固定版本下的重复试验对比 |

不等待三人全部开发结束才联调。每阶段保存可运行版本；每项交付记录负责人、代码提交、配置、复现步骤、结果路径和已知限制。原始大数据按仓库约定保留在 `data/`，将可审查的摘要纳入版本管理。
