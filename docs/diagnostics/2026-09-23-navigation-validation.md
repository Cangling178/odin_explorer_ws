## 低矮小簇过滤

原先随车附近出现的低矮点，在一次采样中连成约 5 × 22 cm、厚约 1 cm 的点簇，最高点约为车体原点上方 3 cm。不能仅凭尺寸认定它一定属于车体或地面；按用户要求，在障碍标记分支增加按尺寸过滤。

规则位于 `explorer_odin/src/small_obstacle_filter.hpp`：

1. 对已有自身包络和高度过滤后的点，在 `base_link` 中使用 PCL 欧氏聚类，邻接距离 4 cm。
2. 仅当簇包围盒最长边不超过 25 cm，且所有点都不高于 `base_link` 上方 4 cm 时删除该簇。
3. 更高的细杆、更大的簇保留；`small_cluster_max_extent=0.0` 可关闭过滤。
4. 清除点云分支不应用小簇过滤，仍保留原来的真实回波。此处描述代码处理范围，不宣称两个独立适配器的输出已通过逐字节一致性验证。

真实低矮小物体若符合这些条件也会被忽略。参数见[适配配置](../../src/odin_explorer/explorer_odin/config/nav_adapter.yaml)，操作与解释见[导航文档](../04_navigation.md)。

| 验证 | 结果 |
| --- | --- |
| 小簇回归测试 | 电脑和 Jetson 均 1/1 通过；覆盖低矮密集小簇删除、较高细杆/较大低矮簇保留、关闭过滤、空输入、保留坐标顺序 |
| 同时开启/关闭过滤对照 | 关闭时近处低矮点约 117～150 个；开启后为 0；较高障碍点仍约 6400 个 |
| 处理输出接收频率 | 双适配器并行诊断时，开启过滤的障碍输出接收约 8.7～8.9 Hz，关闭过滤约 9.9～10.1 Hz；是当次采样结果，不是性能保证 |
| 无明显障碍时近处观测 | 前方 0.2～0.8 m、左右各 0.2 m 区域，最新三帧障碍点为 0，局部代价地图采样代价均为 0 |
| 明显障碍保留 | 同一区域内 0.6～0.8 m 处仍有约 1150 个障碍点，最高约在车体原点上方 26～27 cm |

## 绕障与直行测试

目标通过正式 Nav2 Action 接口提交。路径中心线沿途按约 2 cm 间距采样检查代价地图；该检查不等同于实车轮廓扫掠验收。短时导航测试约 5 秒后取消，未运行至到点成功。

| 场景 | 结果 |
| --- | --- |
| 前方明显障碍，目标约 `(2.275,-0.325)` | 直线距离约 1.29 m，直线穿过实时障碍，静态地图直线上无障碍；两次规划路径约 2.17 m、2.13 m。绕行规划检查的中心线无障碍/未知采样点 |
| 第二个障碍后方目标约 `(2.575,-0.625)` | 直线距离约 1.62 m，绕行路径约 2.07 m，中心线无障碍/未知采样点 |
| 绕障短时控制 | 目标接受；最大采到前进速度约 0.0105 m/s、角速度约 0.258 rad/s；取消确认成功，返回 CANCELED，最终速度为零 |
| 随后的近处直行 | 从约 `(1.008,-0.429)` 朝正前方 0.8 m，目标约 `(1.808,-0.467)`；检查区域无障碍/未知采样，路径约 0.819 m，最大侧向偏移约 0.021 m |
| 直行短时控制 | 最大采到前进速度 0.20 m/s、小幅角速度约 0.0368 rad/s；取消成功，最终速度为零 |

绕障与直行是先后两次实机输入场景，起点和目标不同，不当作同一姿态、同一目标的严格清除延迟测量。

## 障碍清除的解释

用户在 RViz 观察到纸箱放入后出现栅格、拿走后栅格消退，并存在可见更新延迟。另一次实时采样中，前方 0.6～0.8 m 的明显障碍点由约 650～700 个降为 0，连续三帧一致；同一区域代价采样从 37/45 降为 10/45，但不能把余下栅格全部归为纸箱残留。

早期使用较大区域统计、未充分区分背景障碍和更新时间，得出的“纸箱清除不完整”结论已撤回。本次确认障碍标记、移除后的更新及后续直行规划均能工作，未测得精确出现/清除延迟。今后对照应固定起点、目标与物体区域，并等待观测稳定。
