# 架构

[English](02_architecture.md) | 简体中文

目标：在限定实验室区域低速自主探索、避障和同步建图，随后支持地图内定点巡航。当前实现状态见[源码导航](../src/README_cn.md)。

```text
ODIN 点云/位姿 → 所选 SLAM 与栅格生成 → /map → 探索目标选择 → Nav2
新鲜点云 → 障碍物处理 → Nav2 局部代价地图
轮反馈/所选估计器 → 连续里程计与 TF → Nav2
Nav2 / 遥控 → 指令仲裁 → 最终停车控制 → 差速控制器 → F4
```

先验证 ODIN 自带 SLAM 的保存、重定位和地图质量，再决定导航栅格接入方案。厂商地图文件不等于 `nav_msgs/OccupancyGrid`；需要保留占据、空闲、未知以及射线清空语义，处理回环后的地图一致性。点云转二维扫描 + SLAM Toolbox 是待验证备选，不同时启用两个全局定位权威。

目标 TF：`map → odom → base_link → odin_link → 实际传感器坐标`。每条边只有一个发布者。`odom → base_link` 连续；回环修正通过全局变换表达。若以轮式估计器作为局部里程计，ODIN 输出需正确转换到该 odom 定义。不要将 ODIN 已融合的位姿与其 IMU 无相关性处理地重复融合。

保留的 URDF 仅提供外壳和车体模型，没有已标定的设备安装变换；此前的模拟传感器 TF 已删除。预览会发布虚拟轮关节状态，不能与实车 joint_states 混用。

导航须使用实测车体轮廓、制动能力和传感器覆盖。未知区域不视为空闲；缺乏后方感知时不启用盲目后退。探索目标位于边界附近已知可通行位置，并具备路径可达性检查、超时、失败目标暂时屏蔽、活动边界和结束条件。

上电未使能；输入过期、定位失效、越界或通信故障进入停车状态，恢复数据不自动重新使能。F4 独立指令看门狗不能由 ROS 诊断替代。上述运动功能均待实现。

新决策：暂停赛道有序路线方案，以实验室探索建图为主线；保留 Humble 候选与厂商独立工作空间。Jetson 版本组合仍需实测锁定。

新增集成候选：[官方 Odin-Nav-Stack](../third_party/README_cn.md) 使用 ROS 1 与 NeuPAN，不是 Nav2。它已作为独立源码接入；采用桥接还是移植尚未确定，不能与上图 Nav2 主线混为已实现系统。先利用其人工建图、点云保存与栅格转换流程做验证。
