# 精度与速度评测

[English](08_evaluation.md) | 简体中文

当前 Gazebo 独立验收与历史结果见[验证索引](../experiments/README_cn.md)。下文保留通用测量语义；实车独立采集和 ROS 评测接入尚未实现。

## 明确测量对象

确认比赛以车体哪个点评分。在此之前，报告以选定的 `base_link` 控制原点为基准的误差，并明确注明。使用经过标定的俯视录像或另一独立测量参考来评估绝对路径误差。车载估计可用于诊断，但不是真值。

把实测赛道和车体参考点注册到同一米制坐标系。将样本关联到正确的有序赛道分段，包含重复经过交叉点的不同访问。不受约束的最近线距离指标可能错误奖励走错分支的行为。随结果记录赛道测量和相机的不确定度。

## 核心报告

- 有效完赛时间：按顺序经过规定检查点后，从有方向的起点事件到终点事件的时间；未完成试验单独报告。
- 横向均方根误差、平均绝对误差、P95 绝对误差和最大误差。
- 有效测量时间覆盖率和无效区间；丢失样本不是零误差。
- 超出所选容差的时间，并注明该阈值属于内部指标。
- 错误分支事件、重试、人工干预和完成状态。
- 多次运行的成功率、有效时间中位数/离散程度，以及样本数。

## 已包含的离线评测器

`tools/evaluate_run.py` 读取带时间戳、**已经完成路线关联**的横向误差样本，以及一次运行的元数据。它不处理图像、不推断真值、不分配交叉点分支，也不认证元数据中的完赛声明。

CSV 必须含 `time_s,error_m,valid` 列。`valid` 必须精确为 `0` 或 `1`，有效误差必须是有限数值，时间戳必须有限且严格递增。每个样本保持到下一样本或声明的结束时刻，但不超过 `max_sample_hold_s`。未覆盖和无效区间会降低覆盖率。样本必须落在声明的运行区间内。最后一个样本只能覆盖有上限的尾部区间，单个样本不能无限代表整个运行过程。

误差按有效保持时长加权。P95 是累计时间权重达到 95% 时的最小绝对误差。超差判断采用严格的 `>`。同时报告原始经过时间和 `completion_time_s`；对于未完成或出现错误分支的试验，后者为 null。即使全覆盖且误差为零，也必须具有有效的正时长。没有有效时长时，误差指标为 null，而不是完美精度。

元数据包括 `run_id`、`data_kind`、`measurement_source`、`start_time_s`、`end_time_s`、`completed`、`wrong_branch_events`、`tolerance_m` 和 `max_sample_hold_s`。所附 `data_kind=synthetic` 示例只用于演示工具。未来的录包提取和路线关联由 `racer_evaluation` 实现。

## 实验流程

1. 固定路线哈希、标定版本、Git 提交和参数快照。
2. 记录轮胎/地面状况、照明、传感器安装位姿、电池状态和载荷。
3. 启动独立测量与车载记录，验证事件同步。
4. 先运行精度基线，再每次只改变一项控制/速度设置。
5. 用相同起始条件重复每组设置，记录所有尝试。
6. 比较有效完赛时间和误差，而不只看速度；保留失败记录。

保留部分试验不参与调参。将控制和定位结果分别与独立参考比较，区分控制误差与定位误差。认可表面上的速度提升前，检查各分段曲线和交叉点事件日志。

## 拟定测试矩阵

| 场景 | 要检查的失效情况 |
| --- | --- |
| 多个适中速度的直线 | 比例误差、延迟和振荡 |
| 交叉点两次通行 | 错分支或进度跳变 |
| 紧弯和曲率反向 | 前视切弯、轮速饱和 |
| 强/弱光与阴影 | 分割置信度和恢复 |
| 图像丢帧或位姿过期 | 及时停车、不产生虚假的零误差 |
| 控制器重启/指令丢失 | 下位机看门狗 |
| 重复完整路线 | 热、电池和累计漂移 |

该表是实车验证计划，已有仿真证据按版本单独记录。
