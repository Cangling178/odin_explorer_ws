# 04 导航与巡航

本文对应本次新增的实车导航软件入口。开发和验证基线为 Ubuntu 22.04、ROS 2 Humble；Jetson 与电脑应使用兼容的 ROS 2 环境。电脑负责交互显示，ODIN1 接在 Jetson，导航计算在 Jetson 完成。

实现范围：已有二维地图上的目标点导航、地图内障碍物绕行、实时点云障碍物避障，以及 RViz 选定多个点后的顺序巡航。没有增加下位机程序、底盘通信节点或定位失效停车节点。输出到 `/cmd_vel` 为止。

**当前没有底盘执行接口，因此这些代码本身不会驱动真实小车运动。** 接入 ODIN 后可以显示真实位置、点云、地图、规划路径和导航速度；小车要自主到达目标，还需要后续已有的或另行接入的底盘执行接口。2026-09-23 已用 Jetson 上的真实 ODIN 输入验证规划、控制输出和取消归零，电脑 RViz 跨机交互正常。底盘尚未订阅 `/cmd_vel`，所以没有实际行驶到点。

编译、厂商补丁和两台电脑的启动命令见[部署与构建](02_deployment.md)。运行分工与接口见[项目结构](01_project.md)，逐项代码修改和软件验证记录见[修改与验证](05_changes_and_validation.md)。

## 地图与安装标定

### 1. 两种地图需要匹配

`.bin` 是 ODIN 重定位地图，`.yaml + .pgm` 是 Nav2 栅格地图，不能互相替代。

当前工作区存在 `data/maps/lab_02.bin` 和 `data/maps/lab_01_edit.yaml`。当前按用户确认的红圈原点与坐标轴方向采用以下人工对齐关系，地图文件本身不变：

```text
map_from_odin = [0.95, 5.05, 0.0, 0.0, 0.0, -1.5708]
```

原先采用 `(0.0, 4.6)` 米；根据用户后续红框位置，在地图坐标中向右（+X）修正约 `0.95 m`、向上（+Y）修正约 `0.45 m`，现为 `(0.95, 5.05)` 米。平面旋转保持顺时针约 90°。目标是使小车显示在长条紫色区域右侧，并使车尾靠近其上边缘。此调整会同时平移车体和实时点云，不改动静态地图，也不是下发运动目标。此值已设为 `navigation_jetson.launch.py` 的默认值，可通过同名启动参数覆盖。它是当前采用的人工初始对齐关系，尚未经过实时点云叠合精度验证；更换地图时需要重新确定，不能直接沿用。

启动参数 `map_from_odin` 表示 **ODIN 地图原点在二维地图坐标系中的位姿**，格式为：

```text
[x, y, z, roll, pitch, yaw]
```

仅在两张地图已经使用同一坐标系时，才能填写六个零。**不要直接把地图 YAML 的 `origin` 抄进这个参数**：YAML 的 `origin` 是栅格图像相对于地图坐标系的位置，并不等于两套地图坐标系之间的变换。

如果栅格来自同一次 ODIN 建图且未旋转、平移地图坐标，通常可在确认叠合后使用单位变换；如果来源不同，需通过共同墙角或其他地标确定平移与旋转关系。

### 2. 传感器安装外参需要实测

`base_to_imu` 表示 ODIN 内部 IMU 坐标系在车体 `base_link` 中的位姿，格式同上。车体原点沿用现有模型：后轮轴中心，x 向前、y 向左、z 向上。

这是 IMU 外参，不是设备外壳中心位置，也不是雷达外参。`imu → lidar` 由厂商数据提供。启动文件仍要求明确填写安装外参；地图变换已使用上述用户确认的默认值。

### 3. 不叠加原驱动启动入口

默认 `start_driver=true` 已经启动 ODIN 驱动，不要同时再运行厂商完整 launch，否则可能同时占用设备并把另一套 TF 混入导航。

`start_driver=false` 仅用于外部已经提供输入的情况。外部驱动必须使用同样的 TF 重映射、重定位模式和时间对齐设置。本次临时联调也使用这一入口注入传感器数据。

## RViz 操作

### 单点导航

1. 等待地图和机器人出现，确认机器人位置、朝向与现场相符，实时点云与墙体对齐。
2. 等待 Nav2 面板的 `Navigation` 为 `active`。
3. 点击工具栏 `Nav2 Goal`。
4. 在地图空闲区域按下鼠标并拖动，拖动方向为目标朝向。
5. 观察全局路径、局部轨迹、代价地图和面板反馈。点击 `Cancel` 取消当前任务。

### 选定多个点巡航

1. 点击官方面板的 `Waypoint / Nav Through Poses Mode`。
2. 使用 `Nav2 Goal` 依次选择 A、B、C 等点，每个点都可拖动设置朝向。
3. RViz 显示航点标记，选取顺序就是执行顺序。
4. 点击 `Start Waypoint Following`，Jetson 的官方航点执行器逐个导航到这些点。
5. 执行期间查看航点进度与路径，点击 `Cancel` 可取消。

本次巡航使用 Humble 官方 `FollowWaypoints`：按列表执行一轮。若需要回到起点，在列表最后再次选择起点；需要有限的多圈路线，可以按顺序重复选择相应点。没有额外实现无限循环任务管理器。

官方面板另有 `Start Nav Through Poses`，对应经过多个途经点的导航。希望逐点到达并短暂停留时，应选择 `Start Waypoint Following`。

### 障碍物显示和避让

- 地图里已有的墙和桌子，通过静态层进入全局、局部代价地图。
- 临时出现的桌椅或箱子，先出现在橙色实时障碍点云中，再进入代价地图。
- 全局规划会结合实时障碍更新路径，DWB 根据局部代价地图调整速度和转向。
- 障碍移走且传感器重新观测到后方或地面时，射线清除会更新旧障碍。
- 原本就在静态地图中的桌子，即使搬走，也仍保留在静态层中；需要修改栅格地图才能移除其静态占据。
- 传感器看不到的后方、侧方或被遮挡区域不会凭空得到新观测。官方恢复行为包含旋转、倒车，实车使用时应结合 ODIN 视场核对这些动作和车体包络。

## 低矮小簇过滤与 RViz 对照

`explorer_odin/config/nav_adapter.yaml` 配置当前规则：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `small_cluster_tolerance` | `0.04` m | 聚类邻接距离 |
| `small_cluster_max_extent` | `0.25` m | 可删除点簇的包围盒最长边；设为 `0.0` 关闭过滤 |
| `small_cluster_max_z` | `0.04` m | 可删除点簇的最高点，相对 `base_link`，不是离地高度 |

仅当尺寸和最高点条件同时满足时删除整簇。较高细杆和更大的簇保留；真实的低矮小物体若符合条件也会被忽略。过滤仅影响障碍标记，清除回波保持原处理链路。当前近处低矮点在开启过滤后由约 150 个降至 0，明显障碍约 1150 个点仍保留。

RViz 黄色/橙黄色散点为 `/navigation/obstacle_points`。局部代价地图用于局部控制，全局代价地图用于路线规划；可以分别取消勾选显示项，区分点云和栅格。粉色障碍核心及周围膨胀色块都属于代价地图，不应把邻近所有栅格都归因于纸箱。

测试时先在无纸箱条件下固定起点、朝向、目标及观察区域；放入纸箱，等待对应栅格稳定后记录绕行；移走纸箱并离开视野，再等待更新后重测同一目标。记录点云和代价地图各自的时间戳，不把显示或清除延迟当作失败。本次未精确测定清除延迟。详见[实机验证记录](diagnostics/2026-09-23-navigation-validation.md)。

## 建议的操作顺序

先在 Jetson 上确认 ODIN 能用目标 `.bin` 重定位，再核对二维栅格地图与重定位坐标是否一致，填写 `base_to_imu`、`map_from_odin`。随后启动 Jetson 导航和电脑 RViz，手推小车确认模型位置、墙体点云与地图始终重合，再放置并移开一个临时箱子，检查代价地图的标记与清除。

在底盘通信尚未接入阶段，先验证 RViz 单点和多点任务能产生合理路径、导航反馈及 `/cmd_vel`，不要把“已发出目标”当成“小车已经自主到达”。后续有底盘执行接口时，先测试约一米的单点导航，再测试绕开固定桌子、绕开临时箱子，最后使用三个宽敞位置执行一轮航点巡航。先按真实车体核对包络与碰撞高度，再逐步调整速度和到点容差。
