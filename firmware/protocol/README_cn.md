# 电机通信约定（提案）

[English](README.md) | 简体中文

检查开发板后再选择 Jetson 到 F4 的通信方式；CAN 或 UART/USB 串口是候选，不是已确认接线。记录物理传输方式、比特率、帧格式、字节序和数值比例。

必须包含的语义：协议版本、单调序列号、明确使能、带物理单位且有界的目标速度、车轮位置/速度反馈、故障标志、指令年龄、心跳、数据损坏检测和重启行为。拒绝格式错误、过期、非有限和超范围指令。旧数据包不能在停车后重新使能运动。超时处理属于下位机职责，必须在上位机断连时验证。

集成前测试：有效往返、截断数据包、错误校验和、重复/乱序序列、重连、目标饱和和看门狗。基础工程不包含通信实现，也未刷写固件。

## 拟定上位机/F4 边界

上位机差速控制器把车体速度转换为左右轮 rad/s。F4 接收物理轮速目标，执行使能/看门狗逻辑，并在有编码器时完成反馈闭环。反馈应包含累计车轮计数或位置、轮速、状态和设备采样时间。记录计数回绕和时钟转换。除非明确修改上位机约定，否则不要再在 F4 中运行一套独立车体运动学换算。

后续代码按板级支持、编码器输入、电机输出、速度控制、通信和故障/使能状态组织。检查现有固件及外设需求后，再选择 HAL/LL、RTOS 或裸机，以及构建系统。
